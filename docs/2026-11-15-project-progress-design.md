# 项目任务进度条设计（总览页节点进度面板）

## 目标与使用场景

主人是产品经理，要在总览页**一目了然**看到每个被调度项目的整体任务进度：一条 0–100% 的任务进度条，条上按节点分段着色，能看出"当前在哪个节点的哪个部分"，以及派生出的整体百分比。等待重试、今日完成（费用）、待您处理保持现有口径。

现状问题：总览只有"调度会话进度"面板，绑定临时 ACP 会话实体（当前无活跃会话即空白），且只有轮次计数，看不到节点级进展。

## 数据来源（已确认，零新基础设施）

串行推进编排器（V6串行推进、Phase1串行推进等规则的运行 Agent）**已经在维护**机器可读的节点状态文件，位于 `AGENT_AUTOLOOP_HOME`（config.root）顶层：

- `v6-serial.json`：顶层含 `project: /Users/macmini/Desktop/vibeguide`、`nodes`（11 个节点，status 含 done/dev_dispatched/pending，节点带 title/summary/pr_url/review_findings/dispatched_at 等）、`lastNode`、`lastEventAt`
- `phase1-serial.json`：nodes（8 个节点，status 含 done/external_in_progress/blocked）、`lastNode`、`lastEventAt`、`meta`（**无 project 字段**）

控制台只读这些文件并渲染，编排器继续按既有方式维护，不需要新进程。

## 数据契约

### 文件发现

`config.root` 顶层通配 `*-serial.json`，不递归。每个文件是一个"链"（chain）。

### 项目归属映射（按序尝试）

1. 顶层 `project`（绝对路径）→ 与规则 cwd 同一 basename 归一口径匹配
2. `meta.project`
3. 文件名前缀（`v6-serial` → `v6`）大小写不敏感前缀匹配规则名（`V6串行推进`）
4. 都不中 → 归入"未识别"分组照样显示（促使修正），不静默丢弃

### 节点顺序

1. 顶层 `plan: ["node-id", ...]`（**本设计新增的契约字段**，编排器按执行序写入）
2. 降级：`Object.keys(nodes)` 插入序（v6 现有文件即链序；JS 保证解析序）
3. 都不可用 → 按 key 排序

### 状态 → 颜色与默认节点内进度

| 状态 | 颜色 | 默认节点内百分比 | 说明 |
| --- | --- | --- | --- |
| done | 绿 | 100% | 已合并完成 |
| dev_dispatched / in_progress | 蓝 | 30% | 开发已派发/进行中 |
| in_review / review | 靛蓝 | 60% | 独立审阅中 |
| rework | 橙 | 75% | 审阅返工中 |
| external_in_progress | 青 | 40% | 等外部/实机验证 |
| blocked | 红 | 保持上次值，默认 20% | 卡住，需要人看 |
| pending | 灰 | 0% | 未开始 |
| 其它未知状态 | 灰 | 0% | 不报错，向前兼容 |

当前节点可用节点级字段覆盖默认值：`percent`（0–100 整数）与 `part`（字符串，如"审阅返工"）。**本设计新增契约**：编排器在派发/状态变更时写入当前节点的 `part` 与 `percent`，控制台优先采用。

### 整体百分比算法

```
已完成权重 = 链上 done 节点权重和（当前节点之前的节点）
当前节点贡献 = 当前节点(覆盖后)percent × 其权重
整体% = (已完成权重 + 当前节点贡献) / 全部节点权重和 × 100
```

权重：节点可有正整数 `weight`，缺省 1（支持"大节点占多段"）。
当前节点选取：优先 `lastNode`（须存在于 nodes），否则链序上第一个非 done 节点。
保留 1 位小数，展示取整。

## 功能范围（总览页新面板"项目任务进度"）

每行 = 一个项目（有串行状态文件，或今天有活动）。逐行展示：

```
vibeguide                                        会话·待命   30%
┌──────┬──────┬──────┬────────────┬─────┬─────┬─────┬─────┬─────┬────┐
│ 404✓ │ 405✓ │ 406✓ │ ▓▓▓░░ 责任闭环 │ P1a │ P1b │ P1c │ P2  │ P2a │ …  │
└──────┴──────┴──────┴────────────┴─────┴─────┴─────┴─────┴─────┴────┘
当前：责任闭环（P0b）· 审阅返工 60% — "返工1：P2-1已修复；P2-2待补或拆分（决策卡37）"
等待重试 1 · 今日完成 14 · 待您处理 2 张 · 今日费用 $0.50      [PR #430]
```

- 任务条：每节点一段，段宽∝权重，底色按状态色；当前节点段内有二次填充表示节点内百分比；hover 显示节点完整标题与状态。
- 当前行：节点业务标题（取节点 `title`，非节点 id）+ part + 一句话概要（节点 `summary` 截断 80 字）+ PR 链接（如有）。
- 计数行：等待重试 / 今日完成 / 待您处理张数 / 今日费用，全部来自 Hub 规则行与卡片的既有口径（与项目筛选联动）。
- 项目行首：项目名 + 会话状态徽标（有 ACP 会话时）；整体百分比大字右对齐。
- "全部项目"时每项目一行；选中具体项目时只剩该行。
- 无串行文件但有活动的项目：显示计数行与"无节点计划"弱化提示（不显示进度条）。

## 非目标

- 不修改编排器实现与 rules.json 提示词（运行时配置，独立动作）；本设计只读文件，节点级 `part/percent/plan` 字段采用"写了就用、没写按状态默认值"。
- 不做甘特图/时间轴、不做节点依赖图可视化、不做历史趋势曲线。
- 不从目标项目仓库拉取任何文件（数据只在 AGENT_AUTOLOOP_HOME）。
- 不改"等待重试/今日完成/待您处理"的统计口径。

## API 与模块

- 新模块 `src/serial-progress.mjs`：文件发现、解析校验、项目映射、百分比计算（纯函数可测）；mtime 缓存 1 秒。
- `src/server.mjs` 新增 `GET /api/serial-progress`：返回 `{ chains: [{ project, percent, current: {id,title,part,percent}, summary, prUrl, nodes: [{id,title,status,percent,weight}], updatedAt, sourceFile }] }`，仅白名单字段。
- `public/status-sections.mjs`：百分比/状态映射纯函数（与既有聚合同层）。
- `public/views.mjs`：新面板渲染，替换"调度会话进度"面板；旧 sessionProgress 聚合函数下线。
- `docs/scheduling-contract.md` 新增《节点进度上报》一节：要求串行编排器维护 `*-serial.json` 的 `plan` 顺序与当前节点 `part/percent`（写明默认值兜底，不写不阻塞）。
- `AGENTS.md` 模块表补 `src/serial-progress.mjs` 一行。

## 技术与安全

- 只读 `config.root` 顶层固定通配，不接受浏览器传路径；单文件上限 256KB；节点数上限 100；字符串字段截断（title 120 字、summary 300 字）。
- JSON 解析失败/校验不过：跳过该文件并在返回中标注 `error`，不拖垮其它链与整个总览。
- 全部文本走 textContent 渲染（既有约定）；无密钥、无运行状态离开本机。
- 编排器可并发写文件：读以原子方式整体读入（小文件），不做部分解析。

## 失败行为

- 无 `*-serial.json`：面板只显示计数行（保持"按现在来"的那几项）。
- 项目映射失败：归入"未识别"行，照样出条。
- 当前节点缺失/状态未知：百分比按已完成节点算，当前段灰显，行尾标注"节点状态未知"。

## 测试计划

- 单元：状态映射表、权重与百分比算法（含覆盖值、缺失 lastNode、全 done、全 pending）、项目映射三级回退、文件解析与错误降级（临时目录造文件）。
- API：`/api/serial-progress` 返回结构、坏文件不 500、无文件时空 chains。
- 浏览器回归：假 serial 文件渲染任务条、百分比、当前节点 part、项目筛选只剩一行、无文件项目的弱化态、移动端无横向溢出。

## 方案取舍

- **读既有编排状态文件**而非控制台自建进度协议：零迁移成本，今天就有真实数据；代价是字段契约靠文档约束，需编排器配合补 `plan/part/percent`（有状态默认值兜底，不写也能用）。
- **替换"调度会话进度"面板**而非并存：同一屏幕两个进度概念会互相混淆；ACP 会话降级为项目行上的一个徽标。
- 节点段等宽（权重缺省 1）起步，不引入拖拽/编辑。

## 验收

- 总览页每项目一行：任务条分段着色、整体百分比、当前节点+部分+一句话概要一目了然。
- vibeguide（11 节点）与 health-service-core（8 节点）真实数据当天可见。
- 项目筛选联动；等待重试/今日完成/待您处理/费用口径不变。
- npm test 与 npm run test:browser 全绿；控制台无报错。
