# Autoloop 本地控制台设计

## 目标与使用场景

为本机 Autoloop 试点提供一个浏览器控制台，让用户无需记 CLI 命令即可判断试点效果、管理调度规则、处理卡片和查看轮次。未来 Android APK 作为同一控制台服务的另一个客户端。

## 已确认架构

浏览器和未来 Android 客户端通过控制台 HTTP API 工作；控制台服务端持有 Autoloop 本人密钥并调用中台。Autoloop 密钥不进入浏览器或手机。当前服务只监听 127.0.0.1，不开放远程访问。

## 功能范围

- 总览：在线状态、运行/排队/重试/失联数量、待处理卡片、Token 和费用。
- 规则：表单新建和编辑；立即运行、暂停和恢复。
- 轮次：最近结果、错误、会话链接和停止操作。
- 卡片：选项回答、文字回答和结案。
- 自动刷新状态，操作后刷新并显示成功或失败。

## 非目标

本轮不实现公网访问、多用户、多中台、Android 安装包、消息推送、自动交付配置或修改 Autoloop 上游源码。

## 技术与安全

Node.js 24 自带 HTTP 服务和原生 HTML/CSS/JavaScript；无运行依赖。服务端从 `AGENT_AUTOLOOP_HOME/config.json` 读取中台地址和本人密钥。所有上游路径使用允许列表，不接受浏览器传入任意 URL 或密钥。

规则编辑采用表单生成 JSON；服务端先写临时草稿，调用当前安装版 `agent-autoloop check <草稿>` 验证，再原子替换 `rules.json`。写操作校验同源请求、自定义请求头和 JSON 内容类型，不启用 CORS。

未来远程访问需要另加 HTTPS、设备级认证和私网或等价安全通道；当前版本不暗中提供这些能力。

## 方案取舍

采用独立本地服务：比静态状态页多了完整调度能力，比修改上游内嵌页面更容易升级和维护。API 与界面分离，使未来 Android 不需要访问本机密钥或重做业务逻辑。

## 验收

- 单元与集成测试覆盖读取状态、上游错误、操作参数、同源限制、规则校验失败不替换正式文件。
- 在真实试点中台完成页面加载、立即运行、暂停/恢复、卡片回答和停止操作。
- 浏览器无控制台错误，移动宽度可阅读和操作。
- 不消耗模型额度完成控制台自身测试；真实 Agent 只在用户主动运行相关规则时启动。
