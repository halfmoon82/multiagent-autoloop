# Spec：移动端 App 与网页设备授权管理后台

- 状态：Draft for independent review / 待实现
- 日期：2026-11-18
- 上游 PRD：`docs/2026-11-18-mobile-device-admin-prd.md`
- 设计稿基线：`docs/design/2026-11-17-mobile-app/`
- 项目根：`/Volumes/Storage/auto调度`
- 本文档职责：把 PRD 转成可执行的实现边界、模块归属、验收与测试策略；不启动实现。

## 1. Objective

在不修改 Hub 上游核心、不新建第二套业务状态系统的前提下：

1. 交付一个独立移动端前端，复用现有后端服务。
2. 在网页控制台中新增设备授权管理后台，支持绑定、查看、解除授权与审计。
3. 让“待我处理”和节点完成通过手机系统通知触达用户，包含通知栏、锁屏通知与 App 图标角标。
4. 支持锁屏直复、生物识别、多设备同步和系统字体自适应。
5. 首版交付可安装的 Android APK，兼容当前旧版鸿蒙设备；不做 HarmonyOS NEXT 原生包。
6. 保持设计稿确认的交互基线，不重新设计。

## 2. Always / Ask first / Never

### Always

- 遵循 RED → GREEN → Refactor；行为变更先写边界测试。
- 每个实现 worker 使用独立 worktree/分支；主 checkout 常驻 main。
- 移动端与网页管理后台共用同一后端服务，不复制业务状态。
- 所有写操作沿用 Host/Origin、自定义请求头、JSON 与路由允许列表校验。
- 远程访问必须使用 HTTPS 与设备级授权；不得以未认证端口转发或明文 HTTP 暴露本机服务。
- 上游文本用 `textContent` 或等价安全方式渲染。
- 测试使用临时目录、临时浏览器 profile 和假 Hub，不调用真实模型。
- 移动端视觉与交互以已确认设计稿为唯一基线；实现不得擅自改变层级、布局或交互。
- 移动端工程建议放在独立 `mobile/` 工作区或同等独立目录，不与现有 `public/` 网页控制台混用。

### Ask first / existing authorization required

- 真实设备绑定、真实推送供应商配置、真机通知验证、生物识别验证。
- Android APK 打包、签名、安装与真机验证。
- 控制台服务重启、生产环境切换、真实规则变更。
- 任何对外通信、凭据使用或生产数据变更。

### Never

- 不修改 Autoloop Hub 上游核心。
- 不新建第二套执行、恢复或状态系统。
- 不把移动端做成网页控制台的等比缩小版。
- 不让移动端解除其他设备授权。
- 不做自定义语音播报；通知只用手机系统能力。
- 不为高风险操作增加额外生物识别或密码门槛。
- 不把 Autoloop 密钥、设备凭证或用户个人数据写入浏览器、截图、测试快照或日志。
- 不把“运行环境”与“宿主平台开通”纳入本 spec；那是第二份 PRD 的范围。
- 不做 HarmonyOS NEXT 原生包。

## 3. Commands

```bash
npm test
npm run test:browser
git diff --check
```

- 纯逻辑/API：至少 `npm test`。
- `public/`、交互或安全响应头变更：同时运行 `npm run test:browser`。
- 移动端新增页面或通知交互：补充对应浏览器/移动端回归。
- Android 打包与真机 smoke：单独授权，不由 CI 或 PR 合并自动触发。

## 4. Current architecture and change boundaries

```text
移动端 App（独立前端）
  └─ 安全远程入口
       └─ 复用现有控制台 API
            ├─ 总览 / DAG / 会话 / 待办 / 规则 / 轮次 / 产物
            ├─ 系统通知、锁屏直复与 App 图标角标
            └─ 设备授权状态

网页控制台
  └─ 新增设备授权管理后台
       ├─ 生成一次性二维码
       ├─ 查看已绑定设备
       ├─ 解除设备授权
       └─ 审计记录

后端服务
  └─ 继续作为唯一业务状态与安全边界
```

### Likely ownership

- `public/`：现有网页控制台新增设备授权管理页面，不重设计既有页面。
- `mobile/`（建议新增）：独立移动端前端工程与 Android 打包配置，不复制控制台业务状态。
- `src/server.mjs`：新增设备授权、远程访问与移动端所需 API 路由与安全校验。
- `src/device-auth.mjs`（建议新增）：设备绑定、解除、状态与审计。
- `src/notifier.mjs`：扩展为面向移动端系统通知的事件分发；不新建第二套通知状态。
- `src/projects.mjs`、`src/dag-*.mjs`：继续拥有项目发现与 DAG 状态，仅向移动端暴露只读摘要与节点详情。
- `src/session-archive.mjs`、`src/scheduling-session.mjs`：继续拥有会话、归档与续跑语义；移动端只消费 API，不改变会话执行。
- `src/card-*.mjs`、`src/rules.mjs`：继续拥有卡片与规则行为；移动端只复用既有交互，不复制业务规则。
- `src/artifacts.mjs`：继续只读产物发现与读取，不改变安全边界。
- `test/`：对应单元、API、假 Hub、浏览器与移动端回归。

模块名为实现边界建议；若现有模块已拥有该行为，应优先最小修改而非新建同义模块。移动端不拥有业务状态，不得分叉或复制现有控制台逻辑。

## 5. Workstream A：移动端 App 壳、Android APK 与安全连接

### 5.1 Current problem

移动端目前没有独立前端，也没有远程安全访问与设备身份。用户不能在任意移动网络或外部 Wi-Fi 下直接使用控制台，也没有可安装的 APK。

### 5.2 Required behavior

1. 独立移动端前端，复用现有后端。
2. 首次使用通过网页管理后台生成一次性二维码绑定。
3. 打开 App 需要系统生物识别。
4. 支持安全连接、断线重连与错误提示。
5. 任意移动网络或外部 Wi-Fi 可直接使用，不要求 VPN。
6. 远程访问层只转发既定控制台 API，不代理任意 URL，必须使用 HTTPS 与设备级授权。
7. 首版交付可安装的 Android APK，兼容当前旧版鸿蒙设备。
8. 多设备可同时绑定，任意一台提交后其他设备同步状态。
9. 移动端只能查看自身绑定信息，不能解除其他设备授权。

### 5.3 Acceptance

- 手机在任意网络下可打开 App 并通过生物识别进入核心页面。
- Android APK 可在当前旧版鸿蒙设备安装并启动。
- 绑定、断线、重连、错误提示和多设备同步均有测试。
- 移动端不能越权解除其他设备。
- 真实设备 smoke 与 APK 安装需单独授权。

## 6. Workstream B：网页设备授权管理后台

### 6.1 Current problem

网页控制台没有设备授权管理能力，无法绑定、查看或解除移动设备授权，也没有审计记录。

### 6.2 Required behavior

1. 新增设备授权管理页面，作为现有网页控制台的管理区域。
2. 生成一次性二维码供手机绑定。
3. 显示设备名称、系统、最近活跃时间、当前状态。
4. 支持多设备同时绑定。
5. 仅网页管理后台可解除任意设备授权。
6. 解除后设备立即失去访问与通知资格。
7. 记录绑定、解除、重命名等审计事件。
8. 管理后台本身沿用现有安全校验，不新增弱认证入口。

### 6.3 Acceptance

- 生成二维码、绑定成功、查看设备、解除授权、审计记录全链路可测。
- 解除授权后，对应设备立即失去访问与通知资格。
- 网页管理后台可管理任意设备；移动端不能管理其他设备。
- 管理页面不暴露密钥或设备凭证。

## 7. Workstream C：系统通知与锁屏直复

### 7.1 Current problem

当前通知只在桌面端使用系统通知，移动端没有待办与节点完成通知，也无法在锁屏直接回复。

### 7.2 Required behavior

1. 每项“待我处理”对应一条独立系统通知。
2. 每个节点成功完成对应一条独立系统通知。
3. 普通失败、自动重试、调度自愈不通知；若形成待我处理项，只发送该待办通知。
4. 待办通知支持两条路径：进入 App 定位原会话问题；或在系统通知内直接选择、文字回复。
5. 节点完成通知点击后进入对应节点交付详情。
6. 已处理或失效事项不重复提交；失败时题目、选项和草稿保留。
7. 锁屏通知显示项目名称、待办摘要和节点完成详情。
8. 锁屏直复需系统生物识别；进入 App 后高风险操作不额外加验证门槛。
9. App 图标角标、通知栏和锁屏通知统一由系统通知能力承载，角标数量与待我处理数量一致。

### 7.3 Acceptance

- 待办与节点完成通知触发、去重、点击定位和锁屏直复均有测试。
- 通知与 App 内状态同步更新。
- 已处理或失效事项不重复提交。
- 锁屏通知内容显示完整摘要，且不泄露密钥或秘密。
- App 图标角标数量与待我处理数量一致，并在处理后同步清除。

## 8. Workstream D：移动端信息架构与核心页面

### 8.1 Current problem

现有控制台是桌面网页信息架构，不适合直接缩小到手机。用户需要全局项目筛选、DAG 环形图、会话待回答组、产物双入口，以及总览、规则、轮次、待办与执行授权等核心页面。

### 8.2 Required behavior

1. **全局项目筛选**
   - 项目是全局一级筛选，不是各页面局部筛选。
   - 总览、规则、会话、轮次、待办、DAG 与产物均显示当前项目，可切换“全部／具体项目”。
   - 切换后所有 Tab 同步生效，列表内容正确过滤。
   - 项目筛选不改变会话内上下文；进入会话后仍显示该会话所属项目。
2. **移动端核心页面**
   - 总览：运行、重试、完成、待办、项目 DAG 进度与最近动态。
   - 调度规则：运行、暂停、恢复、编辑，保持现有网页能力。
   - 执行轮次：状态追踪、结果摘要、会话链接与停止。
   - 待我处理：独立事项列表，保留决策上下文，支持选项、文字与语音回答。
   - 执行授权：确认目标项目、授权范围与外部动作边界；不新增额外高风险操作门槛。
3. **项目 DAG**
   - 使用环形进度图，不用串行链条表示项目进度。
   - 环形分段表示节点，颜色对应波次，深浅表示状态。
   - 中心显示总进度。
   - 配套信息包括波次节点、槽位、分支、执行 Agent、模型、费用／Token、证据、合并提交、是否等待下游启动。
   - 点击节点可查看节点契约、输入、输出、异常行为与验收示例。
4. **会话与待回答组**
   - 会话列表保留类型筛选、搜索、当前会话、新建会话与已归档与历史。
   - Agent 回复中连续提出多个问题时，以“待回答组”嵌入会话。
   - 待回答组保留原话与背景，显示总数、已答数和进度轨。
   - 每次聚焦一道题，已答题折叠保留，可展开回看。
   - 支持选项、文字与语音输入。
   - 提交后进入下一未答题。
   - 未答数量在会话顶部持续可见。
   - 浏览产物、切换会话、旋转或折叠后，未答进度、草稿与滚动位置不丢失。
5. **产物浏览**
   - 产物有双入口：全局产物管理页；会话流内“本会话产物”。
   - 每个产物显示所属会话、当前任务与路径。
   - 手机：会话 → 全屏产物列表 → 全屏阅读 → 逐级返回。
   - 折叠屏：左侧文件列表、右侧阅读；选择文件只更新右侧。
   - 产物只读；系统分享导出只读副本。
6. **已归档会话**
   - 默认折叠。
   - 展开后显示数量、项目、转录条数与停止原因。
   - “查看”进入只读转录。
   - “继续调度”创建新会话并注入最近 10 轮转录，原记录保留。
7. **规则与待办**
   - 规则仅提供运行／暂停／恢复／编辑。
   - 待办在卡片内提供选项回答、文字回答与结案，不虚构“进入原始会话”能力。
   - 轮次页保留现有“会话链接”能力。

### 8.3 Acceptance

- 总览、规则、轮次、待办、执行授权、DAG、会话、产物与归档会话均可在手机上使用。
- 全局项目筛选在所有主要 Tab 可见并正确过滤。
- DAG 环形图与现有基线一一对应。
- 会话内待回答组、产物双入口与已归档会话可正常使用。
- 规则与待办交互与现有网页能力一致，不新增未确认能力。

## 9. Workstream E：语音、字体与无障碍

### 9.1 Current problem

移动端输入和显示需要适配触屏、语音与系统字体，否则放大字体或折叠屏时会出现截断、遮挡或横向溢出。

### 9.2 Required behavior

1. 语音输入覆盖所有会话输入框。
2. 点击麦克风开始说话，实时转为可编辑文字。
3. 可手动修改、追加语音或撤销。
4. 不因停顿自动发送。
5. 未授权、识别失败或无网络时，可直接使用键盘。
6. 字体大小跟随手机系统设置。
7. 使用原生字体度量，不以网页缩放代替。
8. 放大后采用换行、容器增高和纵向滚动。
9. 不截断、不遮挡、不把正文强制压成横向滚动。
10. 图标视觉保持轻巧，但交互热区扩展至约 44–48 dp。
11. 整卡选项有清晰按压、选中和禁用状态。
12. 适配安全区、系统返回、键盘升降、横竖屏与折叠／展开状态连续性。

### 9.3 Acceptance

- 语音输入状态机覆盖空闲、聆听、转写、失败、无权限和无网络。
- 系统字体放大到 160% 时，无截断、遮挡或横向溢出。
- 触控热区、选中态与禁用态可测试。
- 折叠屏展开/折叠状态连续性有回归。

## 10. Data minimization and audit

1. 只保存设备授权与通知所需的最小数据。
2. 不保存设备凭证、密钥、个人通讯录或无关业务数据。
3. 审计记录只包含操作来源、时间、结果和必要上下文。
4. 通知内容只包含项目名、事项摘要和完成结果，不包含密钥或秘密。
5. 日志、截图、测试快照不得包含 Autoloop 密钥或用户个人数据。
6. 所有绑定与解除操作必须可追溯。

## 11. Test strategy

### 11.1 Unit

- 设备绑定、解除、状态与审计。
- 通知触发、去重、状态同步、锁屏直复与 App 图标角标。
- 全局项目筛选。
- DAG 环形图数据与节点详情。
- 会话待回答组状态机。
- 产物双入口与返回路径。
- 语音输入状态机。
- 字体与触控热区。
- 移动端核心页面数据映射：总览、规则、轮次、待办与执行授权。

### 11.2 API / integration

- 设备授权 API 安全校验与错误转换。
- 移动端与网页管理后台共用同一后端。
- 远程访问层仅转发既定 API，不代理任意 URL。
- 多设备同步与任意一台提交后的状态更新。
- 通知与 App 内状态一致性。
- 产物只读与沙箱边界。

### 11.3 Browser / mobile regression

- 移动端核心页面导航与全局项目筛选。
- 会话内待回答组与产物双入口。
- 锁屏通知直复与生物识别流程。
- 系统字体 160% 布局。
- 折叠屏双栏与状态连续性。
- Android APK 安装与启动（单独授权）。

### 11.4 Real-device smoke

- 真实设备绑定、通知、锁屏直复、语音和字体放大。
- Android APK 在当前旧版鸿蒙设备上的安装与运行。
- 需单独授权，不由 CI 或 PR 合并自动触发。

## 12. Acceptance

1. 手机在任意移动网络或外部 Wi-Fi 下可直接使用核心能力。
2. Android APK 可在当前旧版鸿蒙设备安装并启动。
3. 待办与节点完成通知可稳定触达，且与 App 内状态一致。
4. 用户可在手机上完成待办回答，不丢失上下文、草稿或滚动位置。
5. 项目筛选为全局一级筛选，所有主要 Tab 同步生效。
6. 项目 DAG 使用环形进度图，信息与现有基线一一对应。
7. 会话内可同时看到待回答组、产物与归档历史。
8. 产物可从会话直接打开，并能返回原会话。
9. 系统字体放大到 160% 时，无截断、遮挡或横向溢出。
10. 网页管理后台可绑定、查看和解除设备授权，且移动端不能越权解除其他设备。
11. 多设备同时绑定时，任意一台提交后其他设备同步更新。
12. App 图标角标数量与待我处理数量一致，并在处理后同步清除。

## 13. Out of scope

1. 网页控制台的“运行环境”与“宿主平台开通”改造。
2. Autoloop Hub 上游核心修改。
3. 第二套执行、恢复或状态系统。
4. 移动端解除其他设备授权。
5. 自定义语音播报。
6. HarmonyOS NEXT 原生包。
7. 任何部署、发布或生产数据变更。
