# 审阅分级与合并门禁（通用口径）

> 2026-11-19 主人定。适用于本仓库，以及经 Hub 调度完成的所有目标项目的独立审阅。
> 这是分级口径的唯一来源：`AGENTS.md`、全局 `~/AGENTS.md`、调度规则里的审阅提示词都按本文同步，改口径先改这里。

## 为什么这样定

对 #64、#83、#82 三个 PR 的 48 条 P0–P2 复盘发现：门禁偏紧的主因不是复审范围，而是“不会真实发生的问题也拦合并”。
#82 的 9 条 P0 全部依赖“worker 主动作恶篡改共享 Git 配置”这一威胁模型，而 worker 与控制器本就同一系统用户，拖成 8 轮返工；
每多修一条不会发生的问题，又会引入新的返工问题（首轮后的新问题约 85% 由返工引入）。

## 拦截条件：三条同时满足才算 P0–P2

1. **会真实发生**：按正常使用判断，默认把 worker、作者 Agent 视为合作方而非攻击者。
   以下四类例外按对抗场景审（恶意输入、越权、伪造都要考虑）：
   - 处理外部不可信输入（公网请求、第三方回调、用户上传内容）；
   - 多租户（跨租户隔离、owner 校验）；
   - 真实资金（支付、记账、持仓、计费扣款）；
   - 个人隐私或凭据（个人数据、密钥、令牌）。

   例外里防的是**外部一方**（公网请求者、第三方回调、其他租户、上传者、资金往来的外部方）；worker、作者 Agent、同一系统用户在任何项目里都按合作方看待。
   例外按“本 PR 改到的代码路径是否处理这四类输入或数据”判定，不给整个项目贴标签。
   例如本仓库：浏览器可达的 HTTP 入口（Host/Origin 校验）和密钥不外泄按例外审；worker 篡改共享 Git 配置之类 worker 间信任问题不按例外审。
2. **是这次 PR 造成的**：这次改动引入的，或这次改动让原本不可达的问题变得可触发。
   PR 未改动的旧代码问题不算本 PR 的拦截项。
3. **后果达到该级标准**：

| 级别 | 后果标准 |
| --- | --- |
| P0 | 真实丢钱、丢数据或持久化数据写错、泄露隐私或凭据 |
| P1 | 主流程坏掉、计算或展示结果错、事务半途留下不一致状态 |
| P2 | 常见使用场景下的行为回归或明显错误 |
| P3 | 其余一切：罕见边界、只在人为构造/对抗场景出现（四类例外外）、旧代码问题、测试卫生、可读性与优雅性建议 |

补充：

- 按 `AGENTS.md` 第 7 节必须有的回归测试缺失，不算测试卫生，按所修缺陷的级别定级。
- 测试会必然变红（例如写死日期的定时炸弹、必现的 CI 竞争）按 P1 拦截：CI 红等于主流程坏掉。
- Hub 重试、并发轮次、进程中途退出属于正常使用，由此触发的幂等与竞态问题不算罕见边界。
- 拿不准是否“会真实发生”时，写出触发条件，按能举出的最现实场景定级；举不出现实场景的定为 P3。

## 不拦截的问题怎么处理

- P3 不阻断合并，但必须登记：写进 PR 描述的“已知后续”小节（问题、触发条件、建议修法），需要时由调度方另开任务。
- 复审以核对上一轮 P0–P2 是否修好、修复本身是否引入新问题为主；凡满足三条件的问题，不论哪一轮发现都拦。
- 目标项目的 reviewer 读不到本文件：派发审阅时须把三条件与四类例外写进提示词。
- 返工上限、squash 合并、不直推主干等流程规则不变（见 `AGENTS.md` 第 8 节）。

## 审阅占位：同一 PR 同时只许一方审阅和合并

2026-11-19 PR #116 事故：作者会话与另一会话同时给同一 PR 派 reviewer，先批准的一方直接合并，后到的有效 P2 结论无人处理。

- 审阅前先占位：`node scripts/review-claim.mjs claim --pr <号> [--repo owner/name] --holder <审阅方标识>`。退出码 3 表示他人正在审，立即停止，不审、不合并、不再派 reviewer。
- 合并只能用 `node scripts/review-claim.mjs merge --pr <号> --holder <标识> --head <审过的提交> [--delete-branch]`：非持有者或审完后又有新提交都会拒绝合并（退出码 3）。不得直接 `gh pr merge`。若因返工太久占位已过期，先重新 `claim`，成功后再 `merge`；claim 被他人占住才停止。
- 返工后复审沿用同一持有者，重新 claim 即续期；放弃审阅用 `release`。占位 3 小时未续期视为放弃，他人可接手。
- 占位记在 PR 评论里，以 GitHub 服务器时间判先后，Codex、Claude、Hub 规则共用；持有者标识只能用 ASCII 字母、数字和 `._:-`（最长 64），且每个审阅会话或每次规则触发唯一：`<平台>-<会话 ID 或触发 ID>`，如 `codex-9f94e800`、`claude-8932a769`、`hub-pr-review-7712`。同一规则两次触发不得共用一个标识，否则会被当成续期。
