# 防回退机制（修复台账）PRD — 2026-11-28

状态：已确认（主人 2026-11-28 会话内确认契约 v2）

## 背景与问题

fix1–fix12 系列跨会话执行中暴露三类失效模式：

- **A. 代码回退**：后一轮 fix 的 PR 把前一轮已修好的行为改回去，reviewer 与测试均未拦截。证据：`042e210`（fix9 落盘去掉确认执行范围按钮）→ `1173897`（fix11 再次移除同一入口）；`55c6ba1`（fix12「恢复」产物列表，说明中途改丢过）。
- **B. 调度失忆**：新调度/开发会话不知道历史决策与已修缺陷，重复提问已拍板事项、重复引入被否决方案、把已修复当待修复重做。
- **C. 沉淀缺失（B 的根因）**：会话未遵照乔哈里协作模式及时沉淀——主人拍板事项只留在聊天记录，未落入持久开放区，下一会话开局即失忆。

根因：缺一份机器可读的「已修复缺陷 + 已定决策」台账，且派发、审阅、会话闭环三个环节都不消费它。

## 目标

每个经 auto 调度开发的项目自带防回退机制：

1. 台账存目标项目仓库 `docs/fix-ledger.jsonl`，随代码与分支走，worker 在隔离 worktree 可读。
2. 派发 worker 时按节点写范围注入相关台账条目；调度会话资料包（scheduling-context）开局注入「修复台账/已定决策」一节。
3. reviewer 合并前对照台账核查 diff：触碰台账条目登记的文件必须在 PR 描述显式豁免（`ledger-waiver: <entry-id> <理由>`），否则按 P2 处理。
4. 会话沉淀闭环：主人拍板事项当轮沉淀入台账（必要时入统一知识库），沉淀完成才算该轮闭环。

## 成功标准

- 下一轮 fix 起，台账登记过的已修缺陷零复发。
- 调度会话不再就台账中已定事项重复提问/重复决策。
- 台账条目 100% 可追溯：fix 类挂回归测试路径，decision 类挂决策出处（PR/issue/commit/会话日期）。
- 主人拍板事项当轮沉淀率 100%。

## 非目标

- 不补历史欠账的全量测试覆盖。
- 不改上游 Autoloop 内核语义。
- 不做跨项目共享台账（先单项目）。
- 不引入重型外部记忆服务。
- 不改变乔哈里技能本身的对齐门规则（只补沉淀执行，不改门禁语义）。

## 用户场景

主人发起 fix13 时：调度会话开局自动读到 fix1–12 修复台账与决策记录；派发 worker 时按其写范围注入相关条目；worker 不重复被否决方案；reviewer 合并前确认未回退任何台账项（或 PR 已显式豁免）；主人新拍板的事项当轮落入台账。

## 已拍板决策（2026-11-28，主人确认）

1. 机制落点：控制面本仓库新增通用模块，台账数据存目标项目仓库（`docs/fix-ledger.jsonl`）。
2. 失忆治理：worker 层（台账随分支 + 派发注入）与调度会话层（资料包注入）双层都做。
3. 拦截强度：软拦 + 显式豁免（`ledger-waiver`），不做人工资质硬门禁。
4. 沉淀落点：项目台账（机器可读）+ 统一知识库（跨项目可复用教训）双层；沉淀责任在调度会话，worker 只消费沉淀结果。
