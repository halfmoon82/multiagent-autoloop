# 调度会话重启存活设计（存档 + 一键继续）

## 目标与使用场景

主人为项目开启的调度会话目前只存在于控制台进程内存：服务一重启（升级、修 PATH、
崩溃）会话和聊天记录全部消失（2026-11-15 留学辅导会话因此丢失）。本设计让会话
**重启后留档可回溯、可一键继续**，额度消耗完全由主人主动触发。

## 非目标与不可行边界

- **不做进程级重连**：ACP 会话绑定本进程派生的 codex-acp 子进程与 stdio 管道，
  控制台退出即断，协议层无法跨进程恢复。重启后的"继续"= 用存档转录**新建** ACP
  会话续跑（Codex 自身仍可从项目仓库重建上下文）。
- 不做跨机器迁移、不做多端同步。
- 不在重启时自动拉起会话（重启即烧额度是不可接受的默认）。

## 方案：写穿存档 + 手动一键继续（A+B 组合）

### 存档（写穿）

- 位置：`AGENT_AUTOLOOP_HOME/console-sessions/`（运行目录，与 rules.json 同级信任域，
  不进控制台仓库）。
- 结构：每个会话一个 JSON（`<id>.json`，0600）；列表为目录扫描（无 index 文件，减少写放大）。
  字段：id、project、agent、createdAt、updatedAt、closedAt、endStatus
  （active/closed/error/interrupted）、messages（完整转录）、prompt（首轮调度说明）。
- 写时机：每条消息、每次状态变更即时写入（消息体单条 ≤4KB、单会话存档 ≤1MB，
  超限截断最早消息并记 `truncated: true`）；会话关闭/出错时更新 endStatus。
- 启动加载：控制台启动时读 index，把 `endStatus=active`（上次异常退出）的会话标为
  `interrupted`——这是"重启发生过"的显式证据。

### 继续（手动）

- 调度会话视图把历史/中断会话渲染为**只读卡片**（完整转录可看，输入框不渲染），
  顶部横幅提示"控制台重启后会话已存档"。
- 每张中断/历史卡片提供 **「继续调度」** 按钮：新建 ACP 会话（同项目、同契约），
  首轮提示词注入：原会话转录的**最近 10 轮** + 一句续跑指令（"这是此前调度会话的
  记录，请阅读项目资料后接着推进，先汇报上次中断时的状态"）。
- 继续产生的是一个带 `continuedFrom: <旧id>` 的新会话；旧存档保持不变。

## 界面（样稿见 HTML）

- 调度会话页分两组：活跃会话（现有交互不变）+ 已存档会话（只读 + 继续按钮 +
  结束原因徽标：已关闭/异常/被重启中断）。
- 总览页不新增区域；会话计数徽标只数活跃会话。

## API 与模块

- `src/scheduling-session.mjs`：写穿存档（新增内部方法，对外接口不变）；
  启动时从 `config.root/console-sessions/` 恢复存档列表（只恢复元数据与转录，
  不恢复进程）；`start()` 增加 `continuedFrom` 透传。
- `src/server.mjs`：`POST /api/scheduling-sessions/:id/continue`（校验存档存在、
  项目仍是已发现 Git 仓，然后走正常 start 流程 + 注入转录）。
- `public/views.mjs`：会话视图分组渲染 + 存档卡片；`public/app.mjs` 接继续按钮。
- 安全：存档读写固定目录、文件名 UUID 白名单、加载时形状校验、单文件上限；
  转录按 textContent 渲染（既有约定）。

## 失败行为

- 存档目录不可写：会话功能照旧（内存态），控制台启动日志告警一次，不崩溃。
- 存档文件损坏：跳过该文件并在存档区显示"一份存档无法读取"。
- 继续时项目已不在已发现列表：按钮禁用并说明原因。

## 测试计划

- 单元：写穿/加载/截断/损坏降级/interrupted 标记/continue 注入词拼装（临时目录）。
- API：continue 路由 404/400、注入内容含最近 10 轮、存档不泄漏到活跃列表。
- 浏览器回归：重启后中断卡片渲染、转录只读、继续按钮、继续后新会话出现在活跃组。

## 方案取舍

- **写穿 JSON 而非数据库**：零依赖、可人工检查、与运行目录现有风格一致。
- **手动继续而非自动**：重启不偷跑额度；主人对每次模型消耗保持授权。
- **新建会话续跑而非协议重连**：ACP 限制下的唯一可行路径，且 Codex 从项目仓库
  重建上下文的成本可接受。

## 验收

- 重启控制台后，此前的会话以只读存档出现，转录完整，标"被重启中断"。
- 点「继续调度」生成新活跃会话，注入最近 10 轮与续跑指令，正常对话。
- npm test 与 npm run test:browser 全绿；存档不落控制台仓库。

## 开放点（请主人确认）

1. 存档保留策略：默认最近 20 个会话（含转录）滚动保留，可改。
2. 继续时注入最近 10 轮转录，可改多改少。
3. 中断会话是否也出现在项目筛选下（默认：跟活跃会话同一筛选口径）。
