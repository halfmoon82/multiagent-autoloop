# 调度会话与事件链契约

## 定义

**调度会话**是控制面中的协调上下文：选择任务和模型、创建事件、观察状态、诊断失败、组织独立审阅并处理交付事务。

**执行任务**是目标项目中的具体实现。它在目标项目的隔离工作区运行，拥有自己的需求、代码、测试、Git 提交和发布授权。

调度会话位于本项目不等于目标任务代码属于本项目。

## 调度方职责

1. 读取规则、轮次、卡片、`why` 和相关日志，先判断失败原因。
2. 按任务复杂度、失败成本和审阅风险选择最具性价比的平台/模型。
3. 可自愈的本地脚本、配置、状态和规则问题直接修复，做最小验证后恢复或重触发。
4. 组织开发、独立审阅、返工和合并；保持目标项目工作区与 Git 边界。
5. 对无模型可发现的异常使用定时扫描，命中后再唤醒调度 Agent；相同异常在冷却期内不重复唤醒。
6. 只有设计决策、业务含义、外部授权、凭据、部署目标和不可逆操作等门禁才请用户决策。

“待调度处理”默认由调度方推进，不能把所有开放卡片直接转嫁给用户。

## 模型派发规则

- 调度会话必须根据任务复杂度、失败成本和审阅风险选择最具性价比的平台/模型。
- 独立审阅和资金、数据、安全相关任务优先保证可靠性，不得为省钱降低资金、数据或安全审阅质量。
- 控制台只展示实际发现的模型；费用只能使用 Hub 上报，不能按模型名称猜测。

## 事件链不变量

- 事件分支按真实依赖连接。可并行的部署、开发和审阅不得互相阻塞。
- 特别地，NAS 或其他部署结果不得成为检查远端代码、启动开发或审阅的前置条件。
- 事件 `subject` 使用无空格的稳定 ASCII 标识，例如 `<owner>-<repo>`；自然语言放 `summary` 和 `detail`。
- 外部轮询应先确认候选状态稳定，再发完成事件，避免把一次中间状态当成最终推送。
- 重试必须保留失败原因和尝试次数；调度方处理后要验证并关闭对应异常，而不是只隐藏卡片。

## 控制台展示契约

| 区域 | 必须展示 |
| --- | --- |
| 正在运行 | 最近 5 条规则标题、所属项目、概要、状态和模型 |
| 等待重试 | 最近 5 条标题、所属项目、失败概要、尝试次数和模型 |
| 今日完成 | 最近 5 条标题、所属项目、概要、模型和计费信息 |
| 待调度处理 | 最近 5 条开放卡片、所属项目、失联或停止任务概要 |
| 调度规则 | 当前 Agent、实际发现的模型、权限、触发方式和工作目录 |

任务概要必须展示该任务所属项目；项目优先使用任务上报的项目标识，其次使用调度规则工作目录。无法识别时如实显示“未识别”，不得编造。

计费优先级：已上报费用 → 输入/输出 Token + “费用未上报” → “费用未上报”。不得根据平台或模型名称伪造金额。

## 当前实现与运行时能力的边界

当前公开仓库实现上述状态展示、规则管理和受限操作 API。原试点中的异常扫描、远端轮询、部署和平台包装脚本包含真实运行目录或目标项目配置，因此不作为通用实现直接公开。

这些运行时能力在本契约中保留为明确要求；后续入库必须先泛化配置、去除秘密和私有业务语义，并把现有行为测试一并迁移。文档存在不代表相应运行时脚本已经由本仓库提供。

## 验收示例

1. **部署失败但代码已推送**：开发调度仍继续；部署卡片独立处理，不阻塞开发。
2. **连续重试**：无模型扫描发现异常并冷却去重，调度 Agent 读取原因、修复、验证和恢复。
3. **缺少 NAS 凭据**：调度方不自行扩权，向用户说明缺失项和恢复路径。
4. **WorkBuddy 只有 Token 无费用**：今日完成显示 Token 与“费用未上报”，不显示估算美元金额。
5. **目标任务并行开发**：每个 worker 使用自己的目标项目 worktree，控制面仓库不出现目标业务文件。
6. **无 HOME 的公开环境**：模型标签显示默认文案，不读取任何固定个人账户目录。
