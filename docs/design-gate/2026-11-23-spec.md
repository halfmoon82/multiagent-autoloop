# 设计稿门技术契约：前置确认、基线遵守与无门禁自愈

- 状态：已确认（2026-11-23）

## 1. 原则

设计稿门由“创建前完整性预检”和“创建后遵守与自愈”组成。它不在活跃 run 中新增人工门禁。`codeReviewAccepted` 与 `designConformance` 是两个独立结论，merged/done 不得隐式代表 designConformance。

## 2. 触发与范围

- 新页面、布局、导航、交互流程或视觉状态设计：必须进入设计稿门。
- 需要交互设计但无已确认基线：留在设计阶段，不进入开发调度。
- 既有基线上的缺陷、字段、兼容性修复：沿用原基线。
- 纯后端节点：不加载设计设施。

## 3. 启动前一次确认清单

- 原型、说明、交互验收表和参考渲染一致，无未决产品语义。
- 批准记录覆盖完整范围，manifest/planDigest/designDigest 一致。
- 所有 UI 节点有 `contract.design`；所有 surface/state/viewport/interaction 有节点归属。
- manifest、approval、artifacts、参考渲染、verifier 全部复制到控制器内容寻址冻结存储，sha256 可核验。
- 冻结副本恢复演练成功；批准样例 verifier smoke 成功；每种要求视口均可生成证据。
- 浏览器、依赖、证据目录和至少一种备用采集路径可用。
- reviewer 收到“缺证据不得通过、偏差必须返工、不得中途询问工程选项”的合同。
- 全部通过后原子创建根 run；失败不得留下可派发 run。

## 4. 计划与运行 Schema

```json
{
  "design": {
    "manifestPath": "docs/design/<plan>/design-manifest.json",
    "approvalPath": "docs/design/<plan>/design-approval.json"
  },
  "nodes": [{
    "id": "sessions",
    "contract": {
      "design": {
        "surfaceIds": ["sessions"],
        "states": ["list", "detail", "empty"],
        "viewports": [{"width": 390, "height": 844}],
        "interactions": ["search", "filter", "open-session", "answer"]
      }
    }
  }]
}
```

根 run 保存冻结 designDigest 与冻结包位置；节点 run/attempt 继承同一不可变身份。证据包含 commit/designDigest/contractDigest、coverage、capture/check/visualDiff 文件 hash、采集时间与 renderer 版本。worker 证据只作线索，reviewer 必须能独立重建。

## 5. 运行中无门禁自愈矩阵

| 情形 | 自动处理 | 禁止 |
|---|---|---|
| 基线丢失/损坏/摘要不一致 | 从冻结存储按 hash 恢复并审计 | 读取新稿替代、要求重新批准、gate |
| 证据丢失或身份不一致 | 同 SHA 完整缓存复用，否则精确 commit 重建并重审 | warning 后宣称设计通过 |
| verifier 不可用/输出无效/超时 | 设施重试、净化环境、换采集器或无模型脚本 | 计 worker 实现失败、询问本人 |
| 截图失败/依赖或浏览器缺失 | 修复环境、重建临时 profile、补齐全量 captures | 用部分证据验收 |
| 视觉/布局/交互偏差 | 记录 deviation，正常返工并独立重审 | 静默接受、改阈值或基线规避 |
| worker 多次失败 | 换 worker/模型、拆任务、无模型修复 | 设计专用 blocked/gated、工程选择卡 |
| 合同字段丢失 | 从事务快照与批准覆盖矩阵恢复 | 临场新增产品范围 |
| 原型歧义 | 仅按预批准的确定性优先级消除执行歧义 | worker 选择产品行为 |

设施结果分 `pass / deviation / infrastructure-error / incomplete`；基础设施失败不计 worker 实现尝试。不同 SHA 不复用证据缓存。

## 6. 审阅与验收

- `codeReviewAccepted`：独立代码审阅结论。
- `designConformance`：全部批准 surface/state/interaction 的真实渲染与交互证据符合基线。
- 设计偏差进入正常 review→rework，不是异常门禁；未解决 deviation 不得 designConformance。
- knownDeviations 必须映射合同项和返工记录，不能自我豁免。
- merge 不自行判断设计语义，只接受同一 SHA 的有效独立审阅结论。
- 部署、发布、生产数据变更始终独立授权。
